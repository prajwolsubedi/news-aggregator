# Render Setup Guide

## Overview

Your `render.yaml` file will **automatically create 1 web service** when you connect your GitHub repo to Render:

1. **Web Service** (`ai-news-web`) - Handles subscriptions, API endpoints, and pipeline execution

**Note:** We use **GitHub Actions** as the scheduler (not Render worker services, which aren't available on free tier).

## Architecture

```
┌─────────────────────────────────┐
│   GitHub Actions (Scheduler)   │
│   Runs at scheduled times       │
│                                 │
│   08:30 NPT → POST /run-preprocess │
│   09:00 NPT → POST /run-pipeline   │
└──────────────┬──────────────────┘
               │ HTTP POST (with token)
               ↓
┌─────────────────────────────────┐
│   Render Web Service            │
│   (Flask app)                   │
│                                 │
│   /internal/run-preprocess      │
│   /internal/run-pipeline        │
│   (protected with token)        │
└─────────────────────────────────┘
```

## Cron Jobs: GitHub Actions (NOT Render Worker)

**Important:** Your cron jobs run via **GitHub Actions**, NOT in a Render worker service.

- GitHub Actions triggers at scheduled times (08:30 NPT and 09:00 NPT)
- Makes HTTP POST requests to your Render Flask app
- Endpoints are protected with `CRON_SECRET` token
- Render free tier doesn't have worker services, so this is the solution

## Step-by-Step Setup

### 1. Push Your Code to GitHub

```bash
git add .
git commit -m "Production ready"
git push origin main
```

### 2. Connect Repository to Render

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub repository
4. Render will auto-detect `render.yaml` and create the web service

**OR** create manually:

1. **New** → **Web Service**
2. Connect GitHub repo
3. Settings:
   - **Name:** `ai-news-web`
   - **Environment:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python app.py`
   - **Plan:** Free (or upgrade)

### 3. Create PostgreSQL Database

1. **New** → **PostgreSQL**
2. Name: `ai-news-db`
3. Plan: Free (or upgrade as needed)
4. Note: `render.yaml` will auto-create this if using Blueprint

### 4. Set Environment Variables in Render

Set these in your web service:

#### Required Variables

```
GEMINI_API_KEY=your_gemini_api_key
YOUTUBE_API_KEY=your_youtube_api_key
SERP_API_KEY=your_serp_api_key
RESEND_API_KEY=your_resend_api_key
SENDER_EMAIL=ainews@prajwolsubedi.com.np
REPLY_TO_EMAIL=prajwolsubedi@gmail.com
BASE_URL=https://ai-news-web.onrender.com
CRON_SECRET=your_random_secret_token_here
```

**Note:** Get your `RESEND_API_KEY` from [resend.com](https://resend.com). Make sure your domain (`prajwolsubedi.com.np`) is verified in Resend dashboard.

#### Auto-Set Variables

These are automatically set by Render:

- `DATABASE_URL` - Auto-linked from PostgreSQL database
- `SECRET_KEY` - Auto-generated by Render
- `FLASK_ENV` - Set to `production` in render.yaml

### 5. Set GitHub Secrets

Go to your GitHub repository → **Settings** → **Secrets and variables** → **Actions**

Add these secrets:

```
CRON_SECRET=your_random_secret_token_here
RENDER_BASE_URL=https://ai-news-web.onrender.com
```

**Important:** Use the **same token** for both:

- `CRON_SECRET` in Render environment variables
- `CRON_SECRET` in GitHub Secrets

### 6. Generate Secret Token

Generate a secure random token (use this in both places):

```bash
# On Linux/Mac:
openssl rand -hex 32

# Or use Python:
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## How Cron Jobs Work

### Schedule

- **08:30 NPT (02:45 UTC)** - Preprocessing job

  - GitHub Actions → POST `/internal/run-preprocess`
  - Calls `preprocess_and_create_jobs()`
  - Workflow: `.github/workflows/trigger-preprocess.yml`

- **09:00 NPT (03:15 UTC)** - Main pipeline
  - GitHub Actions → POST `/internal/run-pipeline`
  - Calls `run_pipeline.main()`
  - Workflow: `.github/workflows/trigger-pipeline.yml`

### Security

- Endpoints are protected with `X-Cron-Token` header
- Token must match `CRON_SECRET` environment variable
- Only GitHub Actions can trigger these endpoints

### Implementation Details

- **Preprocessing** uses in-memory data (not JSON files) for reliability on ephemeral filesystem
- JSON files are still created for debugging but code doesn't depend on them
- This ensures compatibility with Render's free tier filesystem limitations

### Workflow Files

Two separate workflow files for better organization:

1. `.github/workflows/trigger-preprocess.yml` - Runs at 02:45 UTC
2. `.github/workflows/trigger-pipeline.yml` - Runs at 03:15 UTC

## Troubleshooting

### GitHub Actions Not Running

- Check workflow files exist:
  - `.github/workflows/trigger-preprocess.yml`
  - `.github/workflows/trigger-pipeline.yml`
- Verify cron schedule is correct
- Check GitHub Actions are enabled for your repo
- Verify secrets are set correctly

### Endpoints Return 401 Unauthorized

- Verify `CRON_SECRET` matches in both places:
  - Render environment variable
  - GitHub Secret
- Check token is being sent in `X-Cron-Token` header
- Verify header format: `X-Cron-Token: <token>`

### Pipeline Not Executing

- Check Render logs for errors
- Verify database connection
- Check all API keys are set
- Verify `run_pipeline.py` exists and works

### Database Connection Issues

- Verify `DATABASE_URL` is set correctly
- Check database is running
- Verify connection string format

## Free Tier Limitations

⚠️ **Important for Free Tier:**

- Web service may **spin down** after 15 minutes of inactivity
- First request after spin-down may be slow (~30 seconds)
- GitHub Actions will wake up the service when triggering endpoints
- Consider upgrading to paid tier for always-on service
